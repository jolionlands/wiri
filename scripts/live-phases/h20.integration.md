## Wiring reference (implemented in shared files by the integration lane)

* Export `pub mod recent_windows_config;` in config/mod.rs; add `pub recent_windows: RecentWindowsConfig` to Config/default. Export overlay/recent_windows in overlay/mod.rs.
* decode.rs: add `#[path = "decode/recent_windows_decode.rs"] mod recent_windows_decode;`; add recent-windows to supported TOP_LEVEL, remove its unsupported branch, dispatch `self.decode_recent_windows(node, &mut cfg.recent_windows)`.
* Engine owns `RecentHistory`, `Option<RecentSession>`, `RecentDebouncer`, `Arc<dyn RecentPreviewSink>` (default Mock in pure tests; `DwmRecentWindows::new()` in daemon). On ordinary focus changes, call history.focus(id, debounce_ms). If Some(deadline), schedule a callback using a Weak engine handle which calls history.expire(generation). None for duplicate pending focus is NOT cancellation; debounce=0 should cancel the outstanding worker. Every sync excludes dead/unmanaged HWNDs and includes all workspaces/outputs, app identity (exe/app-model ID, NEVER title), dimensions, urgency.
* Before opening: cancel debouncer; history.begin(windows, actually_focused, action). This returns an already-cycled frozen session. Repeated cycle actions call session.cycle(action), NEVER begin again. Action scope is opening-only; app filter is selected application. Session frame(monitor_rect, config, monitor_dpi_scale) -> sink.show(frame, open_delay_ms). Subsequent show replaces frame without restarting open delay. No source HWND manipulation until commit.
* Input: compile recent binds with lower priority than normal binds; explicit binds {} replaces defaults. Off disables interception. Use new hotkey worker chord support, including modifier trigger Ctrl+Alt. While open consume Escape/Return/A/W/O/S/Left/Right/Home/End and translate to RecentCommand. Derive directional/first/last/close/screenshot trigger keys from normal binds, ignoring their modifiers; hardcoded keys win. Repeats cycle frozen session. After modifier KEY-UP, call modifiers_changed(any CURRENT physical Alt/Ctrl/Shift/Win still held), not state before key-up. Cancel restores origin; Commit focuses selection, promotes history and hides; Close acts on selection and prunes session; Screenshot uses existing UI. Unrelated *application* keyboard input calls history.keyboard_input(actual_focus), cancels debounce. Navigation/trigger input MUST NOT commit history.
* Window close prunes alive IDs; cancel/hide on empty session, disable/reload, quit. sink.hide is nonblocking and stops its thread/one-shot timer. No joins under engine lock; no engine callbacks from preview thread.
* `scripts/live-test.ps1` dot-sources `lane-a-recent.ps1` after helpers/summary exist, with no daemon running. It does not also source `h20.fragment.ps1`.

## Runtime and validation

Preview host class WiriRecentWindowsHost; diagnostics properties WiriRecentThumbnailCount (successful registrations), WiriRecentSelectedWindow, WiriRecentScope (All=0/Output=1/Workspace=2), WiriRecentPreviewWidth/Height. Host is no-activate/click-through and monitor-local. Real DWM thumbnails update without refresh timers; partially offscreen previews crop source rectangles, do not squeeze. Host exists only for active session; one-shot open timer killed on first firing/teardown. Debounce worker sleeps on a cancellable condition-variable deadline and exits when done; stale generations cannot commit. Sources are never resized/moved by the sink.

Pure tests cover defaults/chords, decoder validation and explicit-empty binds, debounce/stale deadlines/input promotion, repeated cycling, modifier release, scopes/app identity, first/last/prune, geometry/cropping/caps and mock teardown. h20 live gates cover registrations, repeated cycles, source geometry/focus invariance, release/escape, scope commands, cap, debounce/input bypass, app identity vs titles and teardown. Distinct-app/output filtering, off/normal-bind precedence, delayed visibility and close/screenshot need parent integration coverage; no claims of live validation here.
