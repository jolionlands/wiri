# niri vs wiri parity matrix A: layout, behaviour, window rules, effects, animations, gestures

Research only: nothing was built, run, installed or edited; no git commands. Written 2026-10-24 by research agent A.

## Summary

- 226 rows (niri features and every in-scope Action, one row per Action or tightly paired Actions). Status: done 2, partial 85, missing 124, N/A on Windows 15. Priority: P0 41 rows (40 still open), P1 76 (75 open), P2 109 (94 open).
- The two `done` rows are `focus-window-up/down` on stacked columns and per-monitor DPI handling. Almost everything else that looks present is `partial` because it parses but is never acted on, has different semantics, or only exists through IPC.
- Weakest areas: core column/tile operations (column swap actually merges tiles, no tile reorder, no consume-or-expel left/right, no active-tile memory, no centring modes, `maximize-column` does not widen), floats (global, not per workspace, invisible to engine focus), monitors (unplug orphans windows, only left/right moves), window rules (no `exclude`, no OR, most `open-*` properties parsed and never used), nothing drawn per window (no focus ring, border, shadow, tab indicator, insert hint), animations (driver never called, no springs), gestures (only Alt-drag and Alt-wheel; touch code never started).
- Top 5 gaps (full list of 15 in section 19): (1) park or hide scrolled-out columns and stop multi-monitor spill; (2) resolve action targets from the real foreground window, floats included; (3) make the default niri keymap behave like niri (column swap, tile reorder, consume/expel, maximize-column, focus-column-first/last); (4) workspace and monitor model (ordered workspaces, previous-workspace, migration on unplug, directional monitor actions); (5) a niri-compatible action vocabulary and argument grammar so existing niri binds port.

## 0. Sources, legend, method

- niri: main at commit e19df12cf8 (2026-10-22). Latest release tag v26.04 (2026-04-25). `Cargo.toml` still says 26.4.0, so "next release" in the wiki means main-only.
- wiri: branch wiri/shine-20261024 (worktree wiri-shine), about 37.6k lines of Rust. `docs/PARITY.md` was NOT trusted; every status below comes from reading the code path config key -> parse -> Action -> dispatch -> engine -> Win32 call.
- Already-known runtime defects (repositioning loop, IPC starvation, new windows not tiled, SetForegroundWindow refusal, default key names rejected, console window, 238 px columns) are not repeated here.

Status words (first word of the 4th column): `done` = works end to end and matches niri closely; `partial` = parsed or half-wired, wrong semantics, or reachable only by a different path (a feature that parses but is never acted on is `partial`); `missing` = nothing found; `N/A on Windows` = no workable Win32 equivalent for foreign windows.

Release column: `R (ver)` = in a tagged release, version from the wiki "Since" notes; `R?` = believed to be in v26.04 or earlier, but the wiki has no per-action "Since" and I could not verify it offline (uncertain); `main-only` = wiki says "Since: next release" or the symbol only exists on main.

Reference shorthands (niri): `ipc:N` = niri-ipc/src/lib.rs line N (Action enum starts at 194); `in:N` = src/input/mod.rs (action dispatch, `Action::X =>` arms); `scr:N` = src/layout/scrolling.rs; `lay:N` = src/layout/mod.rs; `mon:N` = src/layout/monitor.rs; `flo:N` = src/layout/floating.rs; `cfg/x.rs:N` = niri-config/src/x.rs; `W:Name` = docs/wiki/`Configuration:-Name.md` when that page exists (Layout, Window-Rules, Animations, Input, Key-Bindings, Miscellaneous, Outputs, Named-Workspaces, Recent-Windows, Debug-Options), otherwise docs/wiki/`Name.md` (Tabs, Workspaces, Overview, Floating-Windows, Fullscreen-and-Maximize, Window-Effects, IPC). `W:Gestures` is the overview page Gestures.md; its config page is written out as `W:Configuration:-Gestures`.

Reference shorthands (wiri, all under src/): unique file names are written without directory (`engine.rs` = layout/engine.rs, `workspace.rs` = layout/workspace.rs, `message_loop.rs` = backend/message_loop.rs, `low_level_hook.rs` = input/low_level_hook.rs, `parse.rs`/`types.rs` = config/, `rules.rs` = window/rules.rs, `server.rs` = ipc/server.rs); the ambiguous ones keep their directory (`layout/mod.rs`, `input/mod.rs`, `window/mod.rs`, `backend/mod.rs`).

Effort: S = hours to about a day, M = a few days, L = a week or more or architectural. Priority: P0 = needed to daily-drive, P1 = expected niri feel, P2 = nice to have.

Two engine facts that explain many rows below: (1) wiri workspaces are integer ids in a `HashMap<i32, Workspace>` per monitor (`layout/mod.rs:369`), not an ordered list addressed by index; (2) engine "focus" is the last tiled window the engine saw (`Monitor.focus_window`), not the OS foreground, and floating windows never enter it (`main.rs:1229-1274`, `focus_tiled_window` returns None for anything outside a column). Since Phase 1, item 3, every action resolves its target from the OS foreground window first (`TilingEngine::resolve_action_target`) and only falls back to this focus.

## 11. Window rules: match criteria

## 17. Cross-cutting engine gaps behind many rows

Not tied to one niri feature, but they explain why individual rows are `partial`. Line numbers are baseline.

1. Off-screen columns are never parked or hidden. `calculate_positions_in_section` culls them from the position list (`engine.rs:2202-2207`) and the apply loop only touches listed windows, so a scrolled-out window keeps its last rect. (Related working-tree edit in flight: `parked_rect`, see section 21.)
2. Engine focus is not OS focus. `Monitor.focus_window` is set by wiri's own actions and by `focus_tiled_window` (`main.rs:1245-1274`), which ignores anything not in a column, so a focused floating window is invisible to `close-window`, `toggle-floating`, fullscreen, resize and so on. Actions should resolve their target from `GetForegroundWindow()` first. **Done in Phase 1, item 3.**
3. The applied-state cache (`engine.rs:1656-1674`) is invalidated only by `remove_window` (`engine.rs:1130`). Native title-bar drags, app self-resizes, minimize/restore and maximize leave the engine believing windows are where it put them; `EVENT_SYSTEM_MOVESIZEEND` -> `apply_all` is therefore a no-op (`main.rs:1099-1103`).
4. Window rules are resolved once at add time (`engine.rs:821-870`). Matchers on title, `is-active`, `is-floating`, `is-urgent` cannot react afterwards; niri re-resolves dynamic properties continuously (`W:Window-Rules#dynamic-properties`).
5. Minimize, restore, hide and show of managed windows are not tracked (`backend/hooks.rs:98-117` subscribes to neither MINIMIZESTART nor MINIMIZEEND; `main.rs:1056-1058` ignores HIDE). A minimized tile leaves a hole.
6. Monitor unplug discards the monitor and its workspaces (`engine.rs:771-783`); windows are orphaned (`main.rs:1163-1165`).
7. Action vocabulary differs from niri (`input/mod.rs:176-299`): niri's `fullscreen-window`, `toggle-window-floating`, `toggle-overview`, `toggle-column-tabbed-display`, `focus-window-up/down`, `switch-preset-column-width`, `expand-column-to-available-width`, `move-window-to-monitor-left/right`, `screenshot-screen`, `maximize-window-to-edges` are all rejected as unknown actions (bind is skipped with a warning, `message_loop.rs:273-278`), and niri's `focus-workspace 2` is misread as "workspace named 2" (`input/mod.rs:258-260`). A niri-name alias table plus niri's `SizeChange` / workspace-reference grammar would make niri binds portable.
8. No per-column active tile and no per-workspace focus memory in the baseline (`layout/mod.rs:415-422, 573-609`).
9. The animation pipeline is unwired (section 14): `tick_animations_with_backend` has no caller (`main.rs:656`).
10. Dead or never-started code: touch recogniser (`input/touch.rs`, never started), `FloatManager` (`layout/floating.rs`), `snap_floating_to_corner` (`engine.rs:5701`), the CBT hook (thread-local to wiri only, `backend/cbt_hook.rs:30-52`), `animate_scroll`/`animate_focus_change`.
11. Parsed-but-never-consumed config (all `partial` or `missing` in the tables): `border-radius`, `border-padding`, `focus-ring-gap`, `focus-ring-color`, `focus-ring-inactive-color`, `shadow-opacity/offset/blur/color/spread`, `split-ratio`, `auto-balance` (`parse.rs:432-583`, no readers outside `config/`); rule keys `open-on-output`, `open-in-workspace`, `open-fullscreen`, `open-max-bounds`, `sticky`, `default-height` (stored but unused); `workspace { monitor, layout, follow-on-focus }`; `animations` fields `focus_transition`, `window_move`, `window_resize`, `popup`, `shadow` (`types.rs:995-1006`).
12. Workspaces are hidden with SW_HIDE (`engine.rs:1188-1220`, `2500-2515`), so they vanish from the taskbar and the OS Alt+Tab, and a 750 ms reconciler fights the shell re-showing them (`main.rs:447-459`).

## 18. Claims in `docs/PARITY.md` that the code does not back up

- "Two-finger pinch gesture: maps to overview toggle" - the touch hook is never started (section 15).
- "Tabbed columns within a column" - hidden tabs are not hidden, tab keys do not move focus, no indicator (section 8).
- "`open-on-output`, `open-in-workspace`, `open-fullscreen`, `open-max-bounds` rules" - resolved but never read by the engine (section 12).
- "Maximize column (full work-area height)" and "Move column within workspace" - maximize does not widen the column and move merges tiles into the neighbour (section 2).
- "Center focused column on screen" - cannot centre first or last columns (section 2).
- "Workspace slide animation" and "Animation framework" - off by default, rect animation driver not called (section 14).
- "Focus ring (separate from border)" - colour unused; width was only an inset (section 13).
- "Blur backdrop via DwmEnableBlurBehindWindow" - legacy API, no visible blur on Windows 10/11 (section 12).
- "Per-output `layout {}` overrides" - only the position pass honours them (section 1).
- "Named workspaces" - alias from config order to integer id; not created or pinned (section 6).
- "Alt+right-drag interactive resize" - resize is not written back into the layout (section 15).
- "Overview (DwmRegisterThumbnail)" - the host is a whole-window alpha-0 layered window; thumbnails probably invisible, and there is no mouse interaction (section 9).
