## Legend

- **niri ref**: `niri:<path>:<line>` is a file in the niri tree above, `wiki:<page>` is `docs\wiki\<page>.md`.
- **release or main-only**: `release` = wiki "Since" note at or before 26.04, or the feature predates it. `main-only` = wiki says "Since: next release" (or the code/doc shows it changed after 26.04). `release?` = no Since note anywhere and not listed as next-release; almost certainly released but the exact version is unverified. - **wiri status**: `done` = behaviour matches niri closely enough. `partial` = something exists but is incomplete or approximate, including keys that are parsed and stored but never (or only trivially) acted on; those say "parsed-only" in the evidence column, per the brief that parse-without-effect is never `done`. `missing` = no parser key, handler or code of any kind. `N/A on Windows` = Wayland/Linux-only concept; the closest Windows equivalent (if any) is in the approach column.
- **wiri evidence**: `file:line` in the wiri worktree (`src\...`), or `none found`.
- **effort**: S = under a day, M = a few days, L = a week or more. **priority**: P0 = needed to daily-drive, P1 = expected niri feel, P2 = nice to have. `-` for N/A rows.
- Cells never contain a literal pipe; the Windows approach column says "(approximation)" whenever the Windows mechanism is not an exact equivalent.

## Headline findings (verified in code, not from docs)

1. wiri's "KDL" is not KDL. `src\config\parse.rs` is a 2,417-line line-oriented scanner (`input.lines()`, `splitn(2, whitespace)`, `trim_matches('"')`). There is no `kdl`/`knuffel`/`miette` dependency (`Cargo.toml:18-31`, `Cargo.lock`). Every unknown key and every unparsable value is ignored, a few with a `warn!` (e.g. `scale`, `opacity`) and the rest silently (`_ => {}` at `parse.rs:214,360,391,410,428,581,598,660,785,797,893,946,959`). Bind syntax is `Ctrl+Alt+Left focus-column-left`, not niri's `Mod+Left { focus-column-left; }`, so a niri `binds {}` block cannot be pasted in.
2. Config errors are invisible to the user. `Config::load` almost never fails (`loader.rs:177-188`), `validate_kdl_config` is only called from `wiri-ctl` (`ctl.rs:506`), and a failed reload is only a `warn!` (`reload_config_from_disk`, `main.rs:892`). A tray balloon already exists (`tray.rs:402`) but is never used for config errors.
3. Unlisted defects found while tracing (not in the known-defect list):
   - Bare `Escape` is registered with `RegisterHotKey` (default config `Escape overview-toggle`; `message_loop.rs:618-638`). When overview/resize mode is off the handler just `continue`s, so Escape is consumed system-wide for every application. No `SendInput` re-injection exists anywhere (`grep SendInput` empty).
   - Unknown or unsupported modifiers are dropped, not rejected (`types.rs:931-943`, `_ => {}`). `Mod+T`, `Mod5+T`, `ISO_Level3_Shift+T` therefore register a bare `T` hotkey and steal that key globally. **Fixed in Phase 1:** unknown modifiers are rejected with a warning and `Mod` is understood (rows "Invalid modifier is a config error" and "`Mod` modifier alias").
   - `spawn "prog" "arg" ...` keeps only the first argument (`input/mod.rs:203`), then whitespace-splits it (`message_loop.rs:1279-1296`), so quoted paths with spaces break. **Fixed in Phase 1:** one shared spawner (`hooks::spawner::spawn_argv`).
   - `spawn-at-startup` and IPC `spawn` go through `Spawner::spawn`, which passes the program as `lpApplicationName` to `CreateProcessW` (`spawner.rs:90-101`). By the API contract that parameter is NOT searched on PATH, so bare names such as `wt.exe` (the default config's own example) fail unless they resolve relative to the current directory. Arguments are appended unquoted (`spawner.rs:55-59`). **Fixed in Phase 1.**
   - Config reload debounce is leading-edge only (`loader.rs:97-102`). The first filesystem event loads the file immediately and later events inside 100 ms are dropped, so a non-atomic editor save can apply a truncated file and then ignore the final write.
   - UTF-8 BOM is not stripped (no handling in `src\config`); Windows PowerShell 5.1 writes one, which makes the first line of the file unparsable.
   - `warp-on-focus` and `focus-delay-ms` are parsed and stored but never reach the mouse tracker: `main.rs:465-466` and `main.rs:908-909` (`apply_loaded_config`) hard-code `warp_on_focus: false`, `focus_delay_ms: 200`; `MouseTracker::warp_to_center` (`mouse.rs:97`) has no caller.
   - Touch/pinch gesture support is dead code: `start_touch_hook` (`touch.rs:446`) is `#[allow(dead_code)]` and never called; all `input.touch` keys are stored and never read. Even if it were started, a global `WH_GETMESSAGE` hook installed with a NULL module needs a DLL on Windows (`ERROR_HOOK_NEEDS_HMOD`), so the recogniser could not see other processes' pointer messages.
   - Output config: only `enable`, `scale` (cosmetic) and the nested `layout {}` override are consumed (`main.rs:312-346`, `TilingEngine::set_full_config`, engine.rs:3819-3844). `x`, `y`, `width`, `height`, `mode`, `transform`, `vrr`, `primary`, `mod-key` are parsed and ignored. The default `OutputConfig` has `scale 1.0` and index fallback, so monitor 0's real DPI scale is overridden to 1.0 even with no output block (`types.rs:19-32`, `main.rs:314-336`). Output edits on reload are not applied until the next display-change event (`apply_loaded_config`, `main.rs:898-922`).
   - IPC events `config_loaded`, `workspaces_changed` and `workspace_activated` are defined (`messages.rs:388-405`) and documented, but nothing ever broadcasts them (`grep` finds no emitter).
   - The named pipe name is machine-global (`\\.\pipe\wiri_control`, `ipc/mod.rs:11`). The single-instance probe (`main.rs:140-161`) and the pipe DACL (`D:(A;;GA;;;BA)(A;;GA;;;OW)`, `server.rs:1713`) mean a second logged-in user (fast user switching, RDP) either aborts with "another instance is already running" or ends up with no working IPC. **Fixed:** the pipe is now the pipe of one user in one session (`\\.\pipe\wiri_control_<user>_<session>`, `src/ipc/mod.rs`), and the single-instance check is made against that pipe.

## 18. Top 15 gaps to close first

1. **Global Escape swallow** (S, P0, section 5): the default config registers bare `Escape` with `RegisterHotKey` and drops it outside overview, so no app sees Escape while wiri runs; handle it in the LL hook and pass it through.
2. **Unknown modifiers become bare-key hotkeys** (S, P0, section 5): `Mod+T` silently registers a global `T`; reject unknown modifiers at parse time, then add the `Mod` alias tied to `mod-key`.
3. **`spawn` / `spawn-at-startup` argv and PATH handling** (M, P0, sections 12-13): extra args are dropped, quoted paths split on spaces, and `lpApplicationName` skips PATH so even the default config's `wt.exe` example fails; fix once in a shared spawner (IPC spawn uses it too). **Done in Phase 1.**
4. **Real KDL v1 parser with spans** (L, P1, section 1): the line scanner causes silent typos, the incompatible `Mods+Key action` syntax, missing flags, `/-`, raw strings and the BOM problem; `knuffel` + `miette` (niri's stack) makes niri `binds {}` blocks and bind properties work verbatim.
5. **Visible config errors** (M, P1, section 1): keep the last good config (already true), add a balloon/banner, emit `config_loaded {failed}`, validate on every load, and use a trailing-edge debounce so a half-written save is never applied.
6. **Generic `Action` IPC request plus `wiri-ctl action <name>`** (M, P1, sections 8-9): most bindable actions cannot be scripted today, which blocks bars, scripts and the parity of `niri msg action`. **Minimal version done in Phase 1:** `run_action` / `wiri-ctl action <name> [args]` runs any bindable action through the same code as the hotkey; niri's wire format and event stream are still open.
7. **Event stream per niri's contract** (M, P1, section 10): initial-state replay, `WindowsChanged`/`WorkspacesChanged`/`WindowOpenedOrChanged`/`ConfigLoaded`/`OverviewOpenedOrClosed`, richer window and workspace objects; three declared events are never emitted.
8. **WH_KEYBOARD_LL bind engine** (L, P1, section 5): unlocks Win-key chords the shell owns, `repeat=false`, `cooldown-ms`, `allow-inhibiting`, key-up handling and pass-through; keep `RegisterHotKey` as the fallback for elevated foreground windows.
9. **Configurable mouse and wheel binds** (M, P1, section 5): replace the hard-coded Alt gestures with `Mod+Mouse*` / `Mod+WheelScroll*` triggers and use `GetAncestor(GA_ROOT)` so drags start on Chrome/Electron/Explorer windows.
10. **Screenshot pipeline** (M then L, P1, section 7): PNG + clipboard + `screenshot-path` + notification + `ScreenshotCaptured` first, then focused-output crop, Graphics.Capture windows and the interactive region UI.
11. **Real focus-follows-mouse and warp-mouse-to-focus** (M, P1, section 4): event-driven instead of a 500 ms poll that only touches engine state, honour `focus-delay-ms`, wire the existing `warp_to_center`, add `max-scroll-amount`.
12. **Hotkey overlay that fits and dismisses** (M, P1, section 6): a curated "Important Hotkeys" list instead of a dump truncated to ~29 of ~60 chords, dismiss on any key, `hotkey-overlay-title`, startup show.
13. **Output matching and application** (M, P1, section 11): friendly-name and make/model/serial matching via `DisplayConfigGetDeviceInfo`, re-sync on reload, fix the scale-1.0 default that overrides monitor 0's DPI, then apply mode/position/transform with `ChangeDisplaySettingsExW`.
14. **Named workspaces as real workspaces and `workspace-auto-back-and-forth`** (M and S, P1, sections 4 and 14): names currently alias positional ids that collide with numbered workspaces; back-and-forth is a few lines of engine state.
15. **Elevation and multi-session story** (M, P1, Appendix C): a manifest (`highestAvailable` or signed `uiAccess`) or scheduled-task launch so wiri can manage and hear keys in elevated windows, and a per-user pipe name so a second logged-in user is not locked out.

## Appendix B. docs/PARITY.md claims that the code contradicts (my scope only)

1. "KDL format with hot-reload": a line scanner, not KDL; unknown keys and bad values are ignored (Headline findings, section 1).

## Appendix C. Windows-only hazards with no niri counterpart

- Elevation (UIPI): higher-integrity window/input interaction remains unsupported by the default normal-integrity manager. Phase 2C Lane D documents normal integrity, a same-user interactive highest-privileges scheduled task and signed/protected-location uiAccess in `docs/ELEVATION.md`; neither elevation option is implemented or live-tested. LL hooks, `SetForegroundWindow` and `SetWindowPos` must not be assumed to reach higher-integrity windows without an appropriate token/uiAccess. There is no manifest in the tree (`resources/` has only `wiri.rc` and the default config; `build.rs` embeds nothing). `Spawner::spawn_elevated` only launches children elevated (src/hooks/spawner.rs:209).
- Named-pipe names are machine-global, so IPC and the single-instance probe collide across user sessions.
- `RegisterHotKey` cannot take chords the shell or a GPU hotkey service already owns; the Win key needs the LL hook route.
- Windows PowerShell 5.1 writes a UTF-8 BOM when users script their config; wiri does not strip it.
- The `Run` registry value is written without quotes (src/hooks/startup.rs:96-154), which is unsafe for install paths with spaces.
- The workstation lock moves input to the secure desktop, so lock-screen bind behaviour is not configurable.
- Line numbers are against commit 1532635 (see the baseline note at the top); the live worktree is being modified by another agent, so search for the quoted symbol if a line number misses.
